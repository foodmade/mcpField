图 5 · 每一步的"增量"依据

项目里没有统一的增量开关，每个任务各有判断依据；改任何一步前先看这里

步骤判断依据什么时候会重做强制选项
crawl mcp-registry--since auto = 上次成功且不带 --limit 的抓取开始时间 − 1 小时 → 接口 updated_since；周日不带 since 全量兜底Registry 记录的 updatedAt 变新--since <日期> / --force
crawl skills-shlastmod = min(max(仓库推送时间, 现在−90 天), 现在−7 天)，晚于上次抓取才重抓；新 Skill 必抓；安装量每天整批更新上次抓取后仓库有推送且隔 7 天以上；90 天没推送也刷一次--force
classify输入指纹（名称、简介、标签、工具名、包名、仓库、源站分类、README 开头 1,200 字、分类体系版本）或提示词版本条目信息变化、改 taxonomy、改提示词--force / --all（评估）
publish不增量：事务内整体重建；slug 沿用上次；content_changed_at 只在内容哈希变化时更新每天—
assets / owner-iconsmedia_assets 已成功的跳过；失败 1h → 4h → 16h… 最长 7 天退避；skipped / gone 不再试新图标地址、原图失效--force / --retry-all
github 仓库统计不增量：每天全量刷新全部仓库（约 4.9 万，41 分钟）每天—
github README成功的 7 天后 ETag 条件请求（304 不占额度）；not_found / too_large 30 天后再试；临时错误退避最长 7 天到期--force
translate / translate-tools原文指纹在记忆库里三种语言齐全即完成；人工译文永远算完成原文变化（指纹变 = 新原文）--stale / --recheck / --force
describe事实指纹没变就跳过；照抄源站说明（连续 6 英文词 / 12 汉字）重写 3 次仍不合格则跳过源记录事实变化--stale / --force
overview输入指纹（名称、简介、标签、README 哈希，不含分类）变化或缺某种语言；README 不足或星数低于门槛跳过README 更新、简介变化--stale / --force / --min-stars
readme整篇按 README 哈希；片段按内容指纹查记忆库，跨项目相同段落只翻一次；多次失败片段 deferredREADME 更新 → 只重翻变化的片段--stale / --force / --retry-failed
搜索表 ingest_search按发布层 + 译文 + 自撰简介 + 星数算行指纹，只改有变化的行publish / github / translate / describe 之后自动search-index
IndexNow只推 content_changed_at 不早于本次 publish 开始的条目，每条推 zh/en/ja 三个地址publish 之后自动indexnow --since / --dry-run
