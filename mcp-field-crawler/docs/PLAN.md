# 全网采集、去重与分类计划

> 制定于 2026-10-12。设计细节见 [DESIGN.md](DESIGN.md)，本文只记录要做什么、按什么顺序、怎么验收。
> 每完成一项就更新状态：⏳ 未开始 / 🚧 进行中 / ✅ 完成 / ⏸ 暂缓。
>
> **第一版的原则**：全部按自动规则执行，不做人工复核；拿不准的宁可不合并（最坏情况是网站上多一条重复，而不是两个不同的东西被合成一个）。人工筛查留给阶段 6 的后台系统。

## 1. 目标

1. **全**：MCP 服务、客户端、CLI、Skill、Agent 覆盖主流注册表、包仓库和 GitHub，可以量化地估计覆盖率。
2. **不重复**：同一个东西不论从几个来源采到，网站上只出现一次；不同的东西不会被误合并。
3. **分得准**："其他"占比 < 5%；主分类准确率在评测集上可测、可回归。
4. **可追溯、可重跑**：沿用现有分层——改了合并规则或分类规则，不用重新抓取。

## 2. 原则

- 每个来源各存一份草稿（保留溯源），合并只发生在发布阶段。
- 合并宁缺毋滥：强键相同才自动合并；只有弱键相同时进人工复核，不自动合并。
- 改合并规则、分类规则前先跑**预演**，看数字再落库。
- 新来源先本地 `--limit 10` 跑通，再全量、再上线。
- 遵守各站点条款：不轮换多个 token 绕过限速；Glama 等有署名要求的数据单独评估。

## 3. 阶段

### 阶段 1：身份键修正与合并预演 🚧

目标：在不改动线上数据的前提下，把"哪些草稿是同一个东西"算对，并能随时出报告。

| # | 任务 | 状态 |
| --- | --- | --- |
| 1.1 | 身份键改为**多键**：每条草稿产出全部候选键（Skill 键、仓库+子目录、Registry 名称、npm、PyPI、远程地址、官网），标出强 / 弱 | ✅ |
| 1.2 | 规范化与排除：启动器包（`mcp-remote`、`@smithery/cli` 等）、本地 / 示例地址、平台域名（npm、PyPI、GitHub、目录站）不产生键；官网是 npm / PyPI / 仓库页面时转成对应的键；包名按 npm / PEP 503 规则校验 | ✅ |
| 1.3 | 合并只在**同一类型内**进行；同一强键跨类型出现时记为"相关"（以后写 `entity_relations`），不合并 | ✅ |
| 1.4 | 合并时做**冲突检查**：两组的仓库不同（根目录与子目录不算冲突）、或 Skill 键 / Registry 名称 / npm / PyPI 不同，就拒绝合并并记入报告 | ✅ |
| 1.5 | 没有任何键的草稿（Loop）按 `source:<来源>/<类型>/<ID>` 单独成组 | ✅ |

| 1.6a | 预演中新发现并已处理：镜像仓库 `mcp-mirror/<owner>_<repo>` 归到原仓库；有子目录条目的 monorepo 根目录键不用于合并；合并组的身份键只取本组独有的强键（保证同类型内唯一） | ✅ |
| 1.7 | 人工检查报告：20 个名称不一致的合并组、137 个有歧义的键、72 组官网相同的提示 → 数据量太大，改到阶段 6 的后台里逐条筛查；第一版接受当前自动规则 | ⏸ |
| 1.8 | 人工决定的持久化（强制拆分 / 强制合并）→ 随阶段 6 的后台一起做 | ⏸ |
| 1.9 | 仓库规范化：用 GitHub 返回的仓库当前地址替换旧地址（组织或仓库改名后旧地址会自动跳转，如 `mendableai/firecrawl-mcp-server` → `firecrawl/firecrawl-mcp-server`），并识别 fork；预计能消掉大部分"同一 npm 包、仓库不同"的歧义。`github` 命令已经在抓仓库当前全名，主要是复用 | ⏳ |
| 1.10 | `remap`：用已保存的源记录按新规则重新生成草稿（不联网抓取、不调用 AI），使 `ingest_drafts.identity_key` 与新规则一致；本地实测会变化 478 条（镜像 461、`site:npmjs.com` 14、其他 3）。目前没有功能读这一列，发布阶段之前做即可 | ⏳ |

发现的数据问题：

- **批量灌水**：4 个命名空间各发布了 500 条以上（`io.github.sadri-dridi` 2,365、`io.github.pipeworx-io` 1,791、`io.github.mcp-dir` 1,114、`io.github.mrfentmen` 802），合计 6,072 条；另有 24 个命名空间各 51–500 条。发布前需要质量过滤规则（阶段 4）。
- **增长很快**：9 月新增 13,434 条，10 月前 12 天 8,599 条。
- **没有标题**的 14,142 条里，约 1,300 条名称最后一段是 `site`、`mcp`、`mcp-server` 这类通用词 → 映射器第 2 版改用命名空间里的账号或域名主体（`com.409acost/site` → `409acost`）。
- **只有大小写不同的名称**：列表 42,327 条、入库 42,320 条。库表的唯一键不区分大小写，`io.github.Foo/x` 与 `io.github.foo/x` 存成同一条（GitHub 账号本身不区分大小写，基本是同一发布者重复登记）。
